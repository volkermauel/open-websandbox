# Specification: Rust control plane (broker + runtime)

## Requirement: broker + runtime authored in Rust; router + controller unchanged

The broker and runtime control-plane components SHALL be rewritten in Rust (axum + tokio)
in a single Cargo workspace at repo-root `rust/` (crates `shared`, `broker`, `runtime`).
The router SHALL remain Go; the upstream agent-sandbox controller SHALL remain the vendored
prebuilt image (`registry.k8s.io/agent-sandbox/agent-sandbox-controller:v0.5.3`, byte-for-
byte). "End-to-end memory safety" SHALL be understood as bounded to the authored broker +
runtime; the residual Go bookends (router + controller) SHALL be documented as accepted
residual risk.

### Scenario: cutover is big-bang

- **WHEN** PR-D lands
- **THEN** the chart deploys Rust-built broker + runtime images and NO Python process runs
  in either component (no Python shim, no coexistence).

### Scenario: vendored + router untouched

- **WHEN** the rewrite completes
- **THEN** `chart/templates/upstream/*`, `chart/files/upstream-*`, `chart/crds/*`, and the
  router build are byte-identical to pre-rewrite; only `broker.yaml` + `sandboxtemplate.yaml`
  image refs changed.

## Requirement: contract preservation (HTTP + env + images)

The Rust impl SHALL preserve the externally observable contract exactly: HTTP paths,
methods, request/response JSON shapes, status codes, streaming formats, WebSocket close
codes, Prometheus metric names/labels, env-var names/values, and image names/tags. The Helm
chart SHALL be an image-swap only.

### Scenario: Open Web UI client does not break

- **WHEN** the Rust broker/runtime serve the OWUI-facing surface
- **THEN** every endpoint behaves identically to the Python impl (1:1); the 13 black-box e2e
  tests pass unchanged against the Rust images across the gVisor/runc matrix + the MinIO S3
  scenarios + the pod-env-hardening assertions.

### Scenario: chart default unchanged

- **WHEN** `helm template` runs with defaults
- **THEN** the rendered manifests differ from pre-rewrite only in the broker + runtime image
  references (and nothing else); `helm lint` is clean.

## Requirement: memory-safety enforcement

The `broker`, `runtime`, and `shared` crates SHALL declare `#![forbid(unsafe_code)]`.
Dependencies SHALL be vetted via `cargo-deny` + `cargo-audit`; `clippy -D warnings` SHALL
gate CI. Security-critical paths (workspace path-confinement + per-session-key auth) SHALL
have `cargo-fuzz` + Miri coverage.

### Scenario: no unsafe in our code

- **WHEN** `cargo build` compiles the workspace
- **THEN** no `unsafe` block appears in `rust/{shared,broker,runtime}` (compile-enforced);
  `cargo deny check` + `cargo audit` are clean.

## Requirement: runtime snapshot/restore use native tar + zstd

The runtime `/snapshot` + `/restore` endpoints SHALL stream through the native `tar` +
`zstd` binaries (not Rust tar/zstd crates). The runtime image SHALL therefore retain a base
that provides `tar` + `zstd` plus the tenant-facing data-science toolchain.

### Scenario: workspace round-trips through native tools

- **WHEN** the broker `GET /snapshot`s then `PUT /restore`s a workspace
- **THEN** the tarball is produced/consumed by `tar`+`zstd` with no leading `.` entry, the
  compressed size is capped (`>MAX_WORKSPACE_BYTES` → 413), and the workspace is restored
  byte-identically.

## Requirement: OpenAPI generated from code

The runtime + broker `/openapi.json` SHALL be generated by `utoipa` derives on the Rust
types/endpoints. The hand-written `broker/openapi_spec.py` SHALL be removed. A frozen-
snapshot test SHALL guard the OWUI-facing schema shape against drift.

### Scenario: spec is generated, not hand-maintained

- **WHEN** the Rust app starts
- **THEN** `/openapi.json` is produced by `utoipa` from the code; no hand-written OpenAPI
  artifact exists in the tree; the frozen-snapshot test asserts the generated schema matches
  the recorded OWUI-facing shape.

## Requirement: testing parity

The rewrite SHALL port the Python unit tests to Rust (`#[tokio::test]`), with the 17
`test_safe_path` path-confinement cases reproduced verbatim. The black-box e2e suite
(`tests/e2e/*`) SHALL remain in Python and run unchanged against the Rust images as the
cross-implementation gate. CI SHALL add `cargo fmt --check` + `clippy -D warnings` +
`cargo test` + `cargo deny`/`audit` (+ Miri/fuzz) alongside the kind e2e.

### Scenario: unit + e2e parity

- **WHEN** CI runs on the rewrite
- **THEN** the Rust unit tests cover the same behavior as the Python unit tests (incl. all
  path-confinement cases), and the 13 e2e tests pass against Rust images on gVisor + runc.
